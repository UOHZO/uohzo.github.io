从幻觉到真实：大语言模型事实核查与事实性评估综述

围绕评价指标、幻觉缓解、数据集、模型优化与外部知识检索五个研究问题，梳理大语言模型事实核查与事实性评估的方法、挑战及可靠性要求。

事实核查Fact-CheckingFactuality EvaluationHallucinationRAGLLM

Hallucination to truth: a review of fact-checking and factuality evaluation in large language models（Artificial Intelligence Review，一区top刊）【系统性地综述了大型语言模型在事实核查与幻觉评估方面的研究进展，详细分析了包括RAG、指令微调及多智能体系统在内的核心技术与挑战。即，现有研究如何判断大模型说得是否真实，又通过哪些方法减少幻觉、提高事实可靠性？】

背景

随着大语言模型被应用于新闻、医疗、教育和法律等领域，模型输出的事实准确性开始直接影响现实决策，其生成的幻觉和虚假信息问题已成为学术界和工业界亟待解决的核心难题。问题在于，大模型生成的内容往往语言流畅、表达自信，但其中可能包含错误甚至完全虚构的信息，因此仅凭文字是否自然，很难判断其是否真实。本文系统性地回顾了从2020年至2025年间，针对大型语言模型事实性评估与事实核查的前沿研究。

作者重点指出了三个挑战：

  1. 评价指标不完善：很多指标主要衡量生成内容与参考答案的文字或语义相似度，但“表达相似”并不等于“事实正确”，也难以识别细微的事实错误。例如，传统的 Accuracy、Precision、Recall、F1 适合评价“支持、反对、证据不足”等分类结果，但无法判断开放式回答中的每个事实是否正确。BLEU、ROUGE、BERTScore 等指标主要衡量答案与参考文本是否相似，也不等同于事实正确。目前仍缺少能够同时评价“结论是否正确、证据是否可靠、推理是否合理、解释是否清楚”的统一指标。

  2. 模型存在幻觉：大模型基于概率预测生成文本，训练数据中又可能包含错误、偏见或过时信息，因此可能生成看似合理但实际上没有依据的内容。例如：

    • 与输入或证据矛盾的内在幻觉；
    • 凭空添加、无法从证据中验证的外在幻觉；
    • 由过时知识、错误训练数据、概率生成机制或复杂推理导致的错误。

    当大模型本身被用于事实核查时，问题尤其明显：它可能一边核查别人的陈述，一边生成新的错误证据或推理。因此，事实核查模型不仅要判断原始声明，还要检查自身产生的解释和推理过程。

  3. 数据集存在局限：一些事实核查数据集过于简单，缺少真实声明的复杂性；另一些数据集又局限于特定领域、语言或标签分布，导致模型难以泛化到真实场景。

当前主要解决方向：

  • RAG：从外部知识库或网络中检索证据，让模型基于可验证的信息进行判断
  • 指令微调和领域微调：使用事实核查数据或医疗、新闻等专业领域数据训练模型
  • 多智能体系统：让不同 Agent 分别负责检索、分析、验证或相互检查
  • 自动反馈与自我纠正：让模型检查自己生成的内容并修改错误
  • 知识图谱：利用结构化实体关系帮助模型进行事实验证（这可以合并到RAG吧）
  • 分步骤推理（查询重写）：把复杂声明拆解成多个较简单的子问题，逐步检索和验证

作者特别强调了 RAG，因为它能够为模型提供实时的外部知识和可追溯证据。但 RAG 的效果高度依赖检索结果是否准确、相关和可信。

RQ1 【评价指标】目前使用哪些指标评价大模型事实核查系统？这些指标有什么不足？

事实核查系统实际上包含多个评价对象：

  1. 最终判断是否正确，例如“支持、反驳、证据不足”；
  2. 生成的解释是否符合事实；
  3. 使用的证据是否相关、可靠；
  4. 推理过程是否合理；
  5. 整体回答是否清晰、有用。

不同指标评价的是其中不同部分，不能简单地用一个分数概括整个系统。

1. 传统分类指标

这类指标包括 Accuracy、Precision、Recall 和 F1，主要用于评价事实核查的最终分类结果。例如，一条声明的真实标签是“反驳”，模型也判断为“反驳”，就记为预测正确。如果任务包含“支持、反驳、证据不足”三个类别，通常会计算 Macro-F1，避免样本较多的类别主导最终结果。它们的优点是简单、清晰，便于比较不同模型。但局限也很明显：

  • 只看最终标签，不看模型为什么得出这个结论；
  • 无法发现“结论正确但证据或解释错误”的情况；
  • 数据类别不平衡时，Accuracy 可能产生误导。

例如，模型虽然正确判断一条新闻为虚假新闻，但给出的理由完全错误，传统 Accuracy 仍然会将它记为正确。

2. 词汇和语义相似度指标

这类指标主要用于评价模型生成的解释、摘要或回答与参考答案有多相似。其中包括：

  • BLEU、METEOR、chrF：比较词语或字符重合程度；
  • ROUGE：衡量生成内容覆盖了多少参考答案内容；
  • BERTScore、BLEURT、余弦相似度：比较两段文本在语义上是否相近；
  • CLIP-Score：在多模态任务中比较图像和文本是否匹配。

这些指标可以评价内容覆盖程度和语义相似性，但不能直接判断事实是否正确。

例如：

参考答案：爱因斯坦出生于德国。

模型答案：爱因斯坦出生于法国。

两句话绝大多数词语相同，语义表示也非常接近，因此可能获得很高的相似度分数，但关键事实“德国”被替换成了“法国”。所以，“与参考答案相似”不等于“事实正确”。

3. 事实性与证据支撑指标

这类指标不再只比较文字，而是检查模型生成的声明能否得到证据支持，代表方法包括：

  • LLM-AGGREFACT：整合多个事实性和幻觉数据集，使用人工标注评价声明受到证据支持的程度；
  • LEAF Fact-check Score：把回答拆成多个句子，分别根据外部证据进行验证，计算得到支持的句子比例；
  • ReaLMistake：检测回答中是否存在推理错误或与上下文不一致；
  • NLI或文本蕴含方法：判断证据与声明之间是支持、矛盾还是无法判断；
  • Logical Consistency Matrix：通过否定、合取等逻辑变换，检查模型的回答是否保持逻辑一致；
  • Hit Rate：评价检索结果的前几个文档中是否包含相关证据；
  • IMR和JFR：分别关注回答中的事实错误以及“结论正确但解释存在缺陷”的情况。

这类方法更接近事实核查的真正目标，但仍然依赖高质量的证据和标注。如果作为参照的证据不完整、过时或者错误，那么评价结果也可能不可靠。自然语言中的蕴含关系有时也很复杂，很难通过简单的“支持或反驳”完全表示。

4. 基于大模型的评价

即 LLM-as-a-Judge，即让一个能力较强的大模型充当裁判，判断另一个模型的回答是否正确。评价模型可以完成多种工作，例如把复杂回答拆成独立的事实声明、判断每个声明是否得到证据支持、评价检索文档是否相关、检查回答中是否存在幻觉，以及对答案的事实性、推理质量和解释质量打分等。

与固定的相似度指标相比，大模型能够理解上下文和复杂语义，评价更加灵活，也能降低人工成本。但它存在一个根本问题：

“被用作裁判的大模型本身也可能产生幻觉或偏见”

此外，评价结果可能受到 Prompt 表述、评分顺序和模型偏好的影响。因此，LLM 评价不能天然被视为标准答案，通常还需要与人工标注结果进行一致性验证。

需要注意，Zero-shot、Few-shot、CoT、ReAct 等本身是推理或提示方法，不是评价指标。论文在这一部分提到它们，是因为研究者需要使用事实性指标评价这些 Prompt 方法带来了多大提升。

人工评价

人工评价主要用于判断自动指标难以衡量的内容，例如：

  • 事实是否准确；
  • 解释是否清楚；
  • 证据是否充分；
  • 回答是否有用；
  • 是否存在冗余、偏见或不合理推理。

评价者通常使用 Likert 量表进行评分，例如从 1 到 5 分评价答案的清晰度和可信度。人工评价仍被视为重要的参照标准，尤其适用于医疗、法律等高风险任务。它的缺点是成本高、速度慢，而且不同评价者可能有不同判断，因此需要明确的评价标准和一致性检验。

核心结论

作者认为，评价方法从只评价“最终标签是否正确”，逐渐转向同时评价“事实、证据、推理和解释”。事实核查是一个多阶段任务，最终标签正确并不代表整个核查过程可靠。评价系统必须同时考虑结论、证据、事实陈述、推理过程和解释质量。

任何单一指标都有明显不足。因此，更合理的方向是采用混合评价框架，例如：

  1. 用 Accuracy 或 F1 评价最终判断；
  2. 用 Hit Rate 评价证据检索；
  3. 用事实性指标检查每个陈述是否受到证据支持；
  4. 用 LLM 评价复杂推理和解释；
  5. 用人工评价验证高风险或主观性较强的结果。

RQ2 【幻觉缓解】幻觉如何影响大模型事实核查的可靠性？又可以通过哪些方法缓解？

1. 什么是幻觉

论文将幻觉定义为：模型生成的内容语言流畅、逻辑上看似合理，但事实上错误、缺乏证据、没有意义或者完全虚构。分类如下：

| 分类 | 含义 | 例子 | | --- | --- | --- | | 内在幻觉 | 输出与给定材料直接矛盾 | 材料说“药物无显著疗效”，模型却说“药物疗效显著” | | 外在幻觉 | 输出加入了材料中没有、也无法由材料验证的信息 | 模型凭空补充“该药已完成万人临床试验” | | 忠实性错误 | 回答没有忠实遵循输入文本或检索证据 | 对证据进行错误归纳或张冠李戴 | | 事实性错误 | 回答与真实世界知识不一致 | 给出错误的时间、人物或因果关系 |

2. 幻觉产生原因

  1. 训练目标不保证真实性，仅确保连贯 大模型学习的是“下一个词最可能是什么”，目标是生成连贯、自然的文本，而不是证明每句话都正确。
  2. 训练数据本身包含错误 互联网语料中存在虚假信息、过时内容、偏见和相互矛盾的说法，模型可能把这些内容吸收到参数中。
  3. 参数知识有限且会过时 模型训练完成后，内部知识基本固定。面对训练后发生的事件或不熟悉的问题时，模型可能用一个听起来合理的答案填补知识空缺。
  4. 不能正确利用证据 即使提供了检索文档，模型也可能混淆不同来源、错误归因，或者把多篇文档中的信息拼接成一个不存在的事实。
  5. 对异常输入和虚假关联敏感 分布外问题、诱导性 Prompt，甚至没有意义的输入，都可能触发模型生成自信但错误的回答。

3. 为什么它对事实核查特别危险

事实核查系统通常包含声明理解、查询生成、证据检索、证据判断、结论生成和解释生成等环节。如果大模型在任何一个环节产生幻觉，错误都可能传播到后续流程。

因此，事实核查不能只看最终的“真或假”标签，还必须检查证据是否真实、证据是否支持结论、解释是否与证据一致。作者还指出，真假信息混合的回答会增加人工核查负担，甚至可能让使用者过度相信错误结论。

4. 缓解幻觉的主要方法（五个技术路线）

| 方法 | 核心思路 | 代表工作 | | --- | --- | --- | | 微调与指令微调 | 使用带有声明、证据和真实性标签的领域数据训练模型 | MiniCheck、CliniFact、LEAF | | RAG | 检索外部证据，让回答建立在可验证信息上。（RAG通过外部知识缓解模型知识不足和知识过时，但并不能彻底消除幻觉，如果检索到的文档错误、不相关或相互冲突，RAG 反而可能把外部噪声引入回答） | LLM-AUGMENTER、SELF-CHECKER、MEDICO | | 对抗训练 | 使用诱导性、矛盾性或容易出错的样本增强模型鲁棒性 | CLIMINATOR | | 自动反馈与自我纠正 | 先生成答案，再检测错误并迭代修改（生成回答 → 检测不受支持的内容 → 给出事实性反馈 → 重新生成或局部修改 → 再次验证。有些方法还利用 token 级不确定性。如果模型在某些位置表现出较高的不确定性，就触发额外检索或重新验证。） | LLM-AUGMENTER、LEAF | | 混合与多智能体方法 | 让不同模块分别负责分解、检索、推理和评价 | LoCal、FactAgent、LLM-KG |

一些相关结论

  • 需要专门数据和模型的领域，在特定任务上，领域微调的小模型可能优于通用大模型。
  • 系统不仅要给出真假判断，还应提供证据来源、引用、子声明的验证结果和推理依据，方便用户审计。

核心结论

大模型既可以帮助事实核查，也可能成为事实核查系统中的新错误来源。因此，缓解幻觉不能只依赖“让模型再想一遍”，而需要把领域训练、外部检索、证据验证、自我纠错、结构化知识和人工监督结合起来。当前趋势也从单次生成逐渐转向“分解、检索、验证、纠错”的多阶段核查流程。

RQ3 【数据集】事实核查模型通常使用哪些数据集？数据集质量会带来什么影响？

如果只关注狭义的事实核查数据集，即通常包含“待核查声明、相关证据和真实性标签”的数据集，4.3节主要介绍了以下几类。

| 数据集 | 领域或特点 | 主要用途 | | --- | --- | --- | | FEVER | 基于 Wikipedia 的通用事实核查 | 检索证据，并将声明判断为支持、反驳或证据不足 | | FEVEROUS | 在 FEVER 基础上加入表格等结构化证据 | 评价文本与表格联合证据检索和验证 | | HOVER | 多跳事实核查 | 需要组合多个文档中的证据才能判断声明 | | AVERITEC | 真实世界声明与网络证据 | 评价开放网络环境中的证据检索和声明验证 | | LIAR | 美国政治声明 | 对政治人物的公开发言进行多级真实性分类 | | RAWFC | 新闻和政治声明 | 使用来自真实事实核查网站的声明与证据 | | PolitiFact | 政治事实核查 | 评价政治声明真实性和虚假信息识别 | | SciFact | 科学论文 | 根据科研论文摘要验证科学声明 | | COVID-Fact | 新冠相关信息 | 验证与新冠疫情有关的真实世界声明 | | CliniFact | 临床研究 | 根据临床试验和医学研究证据判断医疗声明 | | Factify | 多模态事实核查 | 结合新闻文本和图片验证声明 | | Multimodal FEVER | 多模态版本的 FEVER | 联合文本与视觉证据完成事实验证 | | MOCHEG | 多模态声明、证据和解释 | 同时完成事实判断与解释生成 | | X-Fact | 多语言事实核查 | 评价不同语言中的声明验证能力 | | CheckThat | 多语言、真实世界声明 | 支持声明检测、证据检索和真实性判断 | | FactBench | 复合型事实核查基准 | 综合评价多种声明和证据类型 | | OpenFactCheck | 集成式事实核查基准与平台 | 评价证据检索、事实验证和解释生成 | | FIRE | 多数据集综合评测 | 评价检索、生成、反馈和事实一致性 |

这些数据集主要服务于事实核查流水线中的三个环节：

  1. 证据检索：能否找到真正相关的文档；
  2. 声明验证：能否根据证据判断支持、反驳或证据不足；
  3. 解释生成：能否给出与证据一致、可追溯的判断理由。

HOVER 等多跳数据集中，一条声明可能对应多篇证据文档：

{
  "claim": "The director of Film A was born in Country B.",
  "label": "SUPPORTED",
  "evidence": [
    {
      "document": "Film_A",
      "text": "Film A was directed by Person C."
    },
    {
      "document": "Person_C",
      "text": "Person C was born in Country B."
    }
  ]
}

模型需要先得到：

Film A → 导演是 Person C
Person C → 出生于 Country B

然后才能判断原声明成立。

因此，标准的证据型事实核查数据集通常包含两部分：

声明数据：claim + label + 黄金证据位置
证据语料库：document_id + title + sentences

RAG 系统先根据声明从证据语料库中检索文档，再根据检索结果预测真实性标签。只有 claim + label、没有证据的数据集，更适合评价分类结果，无法完整评价“模型是否找对并正确使用了证据”。

RQ4 【模型优化】Prompt、微调和领域训练如何影响事实核查效果？

| 方法 | 是否更新模型参数 | 是否使用外部知识 | 核心作用 | | --- | --- | --- | --- | | Zero-shot、Few-shot、CoT | 否 | 通常否 | 通过 Prompt 引导模型核查声明 | | 检索增强 Prompt | 否 | 是 | 让模型边推理边搜索和验证证据 | | 微调 | 是 | 训练阶段使用数据 | 让模型学习特定的核查能力 | | 领域训练与适配 | 通常是 | 可以结合领域知识库 | 提升医疗、科学、政治等专业领域表现 |

1. 基础 Prompt 方法

基础 Prompt 只向模型提供声明、任务说明和少量示例，主要依赖模型内部已有知识。

Zero-shot Prompt

模型只依赖参数中记忆的知识。如果知识不存在、已经过时或本身错误，模型容易凭空猜测。只依赖 Zero-shot 完成事实核查通常不够可靠。

判断下列声明是支持、反驳还是证据不足，并说明理由：

声明：……

Few-shot Prompt

模型通过上下文中的示例学习输出格式和判断方式，Few-shot 通常优于直接提问，但效果依赖示例是否具有代表性。如果没有提供外部证据，它仍然无法解决模型知识错误和过时的问题。

示例1：
声明：……
证据：……
判断：支持

示例2：
声明：……
证据：……
判断：反驳

现在判断：
声明：……

Chain-of-Thought

要求模型先输出中间推理过程，再给出最终判断。CoT 可以让推理过程更加清晰，但论文特别强调“推理步骤更多，不代表事实更加正确”。如果模型一开始使用的知识就是错误的，CoT 可能只是生成一条更加完整、更有说服力的错误推理链。

请逐步分析该声明，最后判断它是否真实。

2. 结合外部检索的 Prompt

Search-augmented CoT

最简单的方式是直接用原始声明进行搜索，然后把搜索结果放入 Prompt。这样比只依赖内部知识更可靠，但直接用完整声明作为查询可能不够精确，难以找到复杂声明所需的细粒度证据。

声明
→ 用声明作为查询进行搜索
→ 获得相关文档
→ 将文档加入 Prompt
→ 逐步推理并判断

ReAct

ReAct 将“思考”和“行动”交替进行。模型可以根据当前推理状态决定是否继续搜索。其优势是能引用外部信息，缺点是搜索结果质量会直接影响最终判断。

思考：我需要确认人物A的出生地。
行动：搜索人物A的出生地。
观察：搜索结果显示……
思考：还需要确认人物A是否导演了电影B。
行动：搜索电影B的导演。

HiSS

HiSS 是一种分层逐步核查方法。它首先把复杂声明拆成多个子声明，然后逐一验证。与普通 CoT 相比，HiSS 不只是要求模型“多想几步”，而是明确规定了声明分解、问题生成、置信度判断、外部检索和最终汇总等步骤。因此，它能够减少遗漏必要推理和凭空生成事实的问题。但 HiSS 需要多次调用模型和搜索工具，计算成本较高，并且仍然对 Prompt 设计和搜索结果敏感。

复杂声明
→ 拆分为子声明
→ 为每个子声明提出问题
→ 判断模型是否有信心回答
→ 没有信心时调用网络搜索
→ 验证各子声明
→ 综合得到最终结论

更完整的模块化框架

SELF-CHECKER、BiDeV、RAGAR 和 PACAR 等方法进一步将事实核查拆分成多个模块：

  1. 识别需要核查的声明；
  2. 将复杂声明原子化；
  3. 生成检索查询；
  4. 检索并筛选证据；
  5. 判断证据是否相关；
  6. 分别验证子声明；
  7. 综合生成最终结论和解释。

这些方法的共同特点是：不让一个 Prompt 一次性完成全部工作，而是把事实核查变成结构化的多阶段流程。

3. 微调事实核查模型

微调与 Prompt 的根本区别是：微调会更新模型参数，使模型真正学习事实核查任务。论文主要介绍了三种路线。

微调小型 Transformer

使用带有“声明、证据、标签”的人工或合成数据训练 RoBERTa、DeBERTa、T5 等模型，使其判断声明是否受到证据支持。MiniCheck-FT5、RBTA 和 DBTA 等模型在特定事实性基准上能够超过 GPT-4。这说明对于明确的证据验证任务，经过针对性训练的小模型不一定比通用大模型差。

使用大模型辅助小模型

ARG 和 ARG-D 让大模型生成分析理由，再让小模型选择性利用这些理由完成虚假新闻检测。这里的大模型主要充当“理由提供者”，经过微调的小模型负责最终分类。这样可以同时利用大模型的解释能力和小模型的稳定性、低成本优势。

将微调模型作为验证器

有些系统会先检索证据，然后把经过指令微调的模型作为 Verifier：

复杂声明
→ 原子声明拆分
→ 证据检索与重排
→ 微调后的验证器判断
→ 生成可信度报告

例如 Yours Truly 先使用 Claim Atomizer 拆分复合声明，再从事实核查数据库中检索匹配证据，最后由模型完成判断。论文报告称，声明原子化是其性能提升的重要来源。

4. 领域训练与适配

领域适配主要有三种方式：

  1. 使用领域数据微调小模型；
  2. 使用领域指令和数据微调大模型；
  3. 在推理时连接领域知识库、论文库或知识图谱。

领域微调的小模型在特定任务上经常优于通用大模型。原因不是小模型的知识更多，而是它更加熟悉该领域中的术语、标签标准和证据判断方式。

RQ5 【外部知识检索】RAG 如何被整合到事实核查系统中？其优势和挑战是什么？

1. RAG 为什么适合事实核查

普通大模型主要依赖参数中存储的内部知识，可能存在知识缺失、过时或错误。RAG 在推理阶段从网络、文档库、知识图谱或专业数据库中检索外部证据，然后让模型根据证据判断声明真假。

它主要带来三个好处：

  1. 获取模型训练结束后出现的新信息；
  2. 减少模型依赖内部知识进行猜测；
  3. 提供证据来源和引用，使结论可以追溯。

需要注意，RAG 不会直接修改模型参数，而是在模型生成答案时补充外部信息。

2. 基本的 RAG 事实核查流程

一个完整流程通常是：

待核查声明
→ 声明拆分
→ 查询生成
→ 外部证据检索
→ 证据筛选与重排
→ 根据证据验证各子声明
→ 汇总真假结论
→ 生成解释和引用

例如声明：

“电影A的导演出生于国家B，并于2010年获得奖项C。”

系统可以拆成三个子声明：

  1. 电影A的导演是谁；
  2. 该导演是否出生于国家B；
  3. 该导演是否在2010年获得奖项C。

然后分别生成查询、检索证据并验证，最后综合各子声明的结果。

3. RAG 在事实核查中的几种使用方式

3.1 一次性检索

最基础的方式是根据原始声明检索若干文档，将文档放入 Prompt，然后让模型判断真假。这种方法简单，但原始声明可能包含多个事实，单个查询难以找到所有必要证据。

Claim → Retrieve → Verify → Verdict

3.2 声明分解后检索

先把复杂声明拆成原子声明，分别生成查询和检索证据。这样可以提高证据的针对性，也能明确指出原声明中究竟哪个部分有误。SELF-CHECKER、PACAR 等系统都采用了类似思想。

3.3 Fact-Check-Then-RAG

普通 RAG 是“先检索，再生成”，Fact-Check-Then-RAG 则先检查模型回答中的每个事实，再针对未通过检查的内容进行检索。这种方法比对所有内容进行无差别检索更有针对性。论文介绍的 LEAF 就采用了这一思路。

模型初始回答
→ 分解为多个事实
→ 检查每个事实
→ 找出不受支持的事实
→ 仅针对这些事实检索
→ 根据新证据重新生成

3.4 迭代式 RAG

一次检索可能无法获得足够证据，因此 FIRE、LLM-AUGMENTER 等方法使用多轮循环。系统会根据当前验证结果决定是否继续搜索，而不是固定只检索一次。

检索证据
→ 验证声明
→ 发现证据不足
→ 修改查询
→ 再次检索
→ 重新验证

3.5 多智能体 RAG

LoCal、PACAR 等框架让不同模块或 Agent 分别负责：

  • 声明分解；
  • 查询规划；
  • 证据检索；
  • 数值计算；
  • 实体消歧；
  • 逻辑和因果推理；
  • 最终验证。

这种方式适合多跳、因果、数值或证据冲突等复杂声明，但会增加调用次数和系统成本。

3.6 强化学习优化检索

传统检索器主要根据查询与文档的相关性选择结果，但“语义相关”不一定意味着“能够支持事实核查”。FFRR 等方法将下游验证器的反馈作为奖励。这样优化的是“文档对事实验证是否有用”，而不只是文本相似度。

检索器选择文档
→ 验证器判断文档是否有助于核查
→ 将验证效果反馈给检索器
→ 检索器逐渐学习选择更有用的证据

4. RAG 的主要问题与解决思路

| 问题 | 具体表现 | 论文总结的解决思路 | | --- | --- | --- | | 检索效率低 | 大规模网络搜索消耗时间和计算资源 | 使用轻量级 NLI 模型、优化检索器 | | 找不到证据 | 专业知识没有公开、没有数字化或难以索引 | 使用 PubMed、教材、领域知识库等专业语料 | | 检索结果存在噪声 | 相关文档不一定真正支持或反驳声明 | 重排、相关性评分、TopK筛选 | | 上下文过长 | 大量文档超过模型上下文窗口 | 只保留前三到四篇文档，压缩和整合证据 | | 来源本身不可靠 | 搜索结果可能包含广泛传播的虚假信息 | 检查来源、证据出处和跨来源一致性 | | 证据相互冲突 | 不同来源给出不同结论 | 显式表示冲突证据，分别评估来源和支持关系 | | 复杂推理困难 | 证据分散在多个文档中，需要因果或数值推理 | 声明分解、动态规划、多智能体和专用工具 | | 领域适配不足 | 通用 RAG 不理解医疗或科学证据标准 | 使用领域语料库、领域模型和专业知识图谱 |

论文特别强调，不是检索文档越多越好。过多文档会引入噪声并分散模型注意力，一些研究发现只保留最相关的三到四篇文档反而更有效。

5. 论文列举的性能提升

论文汇总的实验结果表明，外部证据通常能够明显提升事实核查表现。例如：

  • 在 PolitiFact 上，为 GPT-4 提供外部上下文后，非模糊声明的准确率从75%提高到89%；
  • Fact-Check-Then-RAG 将 Llama 3 70B 在 PubMedQA 上的准确率从60.6%提高到73.6%；
  • 即使只加入一个没有专门优化的检索器，也能比直接 Prompt 获得更高的 F1。

这些结果说明，RAG 的提升不完全来自更复杂的推理，很多时候仅仅是因为模型获得了原本不知道的外部证据。

6. 核心结论

事实核查中的 RAG 正在经历以下变化：

依赖内部知识
→ 一次性检索
→ 声明分解与细粒度检索
→ 多轮检索和验证
→ 验证结果反馈检索器
→ Agent动态规划检索与推理

RAG 能缓解知识过时和幻觉，但不能保证正确。如果检索到的证据错误、不相关或被模型错误理解，系统仍然会得出错误结论。真正可靠的事实核查 RAG，需要同时解决“找对证据”和“正确使用证据”两个问题。

未来重点应从单纯提高最终准确率，转向保证整个事实核查流程都可验证、可解释且能够追溯。

此外，当前大模型主要依靠语言模式完成事实核查，不一定严格遵循逻辑规则。例如，模型可能分别认可两个相互矛盾的声明，或者在面对否定、合取、析取和条件关系时得出不一致结论。可以将大模型与符号推理、知识图谱或逻辑系统结合。例如，将复杂声明转换为原子命题和逻辑关系 (A∧B)→C，然后分别验证 A、B 和 C 的证据，再按照明确的逻辑规则计算整体结论。这样可以避免模型仅凭语言直觉跳到最终答案，也更容易发现具体是哪一个原子事实或逻辑关系发生了错误。但目前神经模型与符号系统的结合仍处于早期阶段，主要困难是如何准确地把自然语言转换成结构化逻辑，以及如何让这种方法扩展到大规模、复杂的真实声明。
