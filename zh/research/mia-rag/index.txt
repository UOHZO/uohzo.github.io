17:T3581,> **核心问题：** 现有 RAG 在长文档中主要依赖局部、证据级信号进行检索和生成，缺少对整篇文档的全局语义认知。我们提出 **Mindscape-Aware RAG（MiA-RAG）**：先通过层次化摘要构建文档级 **Mindscape**，再用同一全局语义表示同时条件化检索器与生成器，使检索器能够在全局主题框架下定位证据，生成器能够在同一框架下整合分散信息。

## 概述

人在理解长文本时，并不会只根据眼前的一小段信息进行判断，而会形成对整个主题或文档的整体印象，并利用这种全局语义框架解释新的局部信息。这种能力称为 **心境感知能力（Mindscape-Aware Capability）**，并把它引入 RAG。MiA-RAG 的核心做法可以概括为：

`长文本 → 层次化摘要 → Mindscape S → MiA-Emb 检索 → MiA-Gen 生成`

其中：

- **Mindscape**：通过自底向上的层次化摘要得到的文档级全局语义表示；
- **MiA-Emb**：将 `Query + Mindscape` 一起编码，使 query embedding 同时保留查询意图和文档全局语义；
- **MiA-Gen**：将 `Mindscape + Retrieved Chunks + Query` 一起输入生成器，使模型在全局语境中理解和整合局部证据。

最终希望获得三种能力：

1. 利用全局语义补充 query 中缺失或不明确的信息；
2. 让 query 表示更靠近当前文档真正相关的语义区域；
3. 在全局语义框架下整合分散在不同 chunk 中的证据。

![对比](/assets/research/mia-rag/comparison.png)

在五个长上下文 benchmark 上，完整的 **MiA-RAG-14B** 获得最佳平均表现，整体优于 vanilla-RAG-14B 和 vanilla-RAG-72B。此外，我们不仅比较了最终任务指标，还分析了模型内部表示和注意力变化。结果表明，Mindscape 会改变 query 的 embedding，使其更接近正确的文档语义区域；同时，检索器和生成器都会关注与当前问题相关的 summary 信息，并据此选择和整合局部证据。因此，性能提升并不是简单来自“多输入了一份摘要”，而是模型学会了利用全局语义指导检索和推理。


## 为什么做这个工作？

### 1. 从长上下文 RAG 的实际问题出发

RAG 是处理长文档的一种常见方案：先把长文档切成 chunks，根据 query 检索少量相关片段，再让生成模型基于这些片段回答问题。但标准 RAG 有一个结构性问题：

> **检索器和生成器看到的主要是局部证据，却缺少对“整篇文档在讲什么”的显式认识。**

这在长文档中尤其明显。一个 query 的含义可能依赖整本书、整份报告或整个项目的背景；真正需要的证据也可能分散在文档不同位置。只根据 query 与局部 chunk 的相似度检索，很容易出现两类问题：

- **检索阶段**：query 本身语义不足或存在歧义，retriever 不知道应该进入文档中的哪个语义区域；
- **生成阶段**：即使检索到了正确证据，generator 也可能缺乏全局背景，无法正确理解不同证据之间的关系。

### 2. 为什么想到 Mindscape？

论文借鉴心理学和神经科学中的相关认识：人在理解熟悉主题或长篇内容时，会形成一个整体性的语义表示；当主题再次出现时，这种全局记忆会被激活，并影响后续的信息解释、检索和推理。

### 3. 这项工作的关键不是“给 RAG 加摘要”

表面上看，MiA-RAG 只是使用了 summary，但我们的方法是**将 Mindscape 作为 retrieval 和 generation 共享的全局背景信息，并训练模型主动利用它。**

实验也专门验证了这一点，对 vanilla embedding model 直接拼接 summary 甚至会降低检索性能。只有经过 mindscape-aware training 后，模型才能较好地融合 query全局上下文。


## 这项工作的挑战是什么？

核心 insight 是把人类的全局语义认知引入 RAG，但让这个方法 work 起来，需要解决如下挑战。**

### 挑战 1：如何把抽象的 Mindscape 变成可计算的表示？

“人对整篇文档有整体印象”是认知层面的描述，不能直接输入模型。论文需要找到一个足够紧凑、又能够表达文档全局语义的外部表示。

MiA-RAG 采用**层次化摘要**：先总结每个 chunk，再将 chunk summaries 按顺序汇总成 document-level summary，并把最终 summary 作为 Mindscape \(S\)。

这样做的原因是：

- 能压缩超长文档；
- 保留整体主题、人物、事件和关系；
- 同一份 Mindscape 可以被多个 query 复用；
- 层次化结构允许文档变化时只更新受影响路径。

### 挑战 2：如何让 Retriever 真正利用全局语义，而不是被摘要干扰？

如果简单把 `query + summary` 拼起来送给普通 embedding model，summary 的大量信息可能淹没 query 本身的检索意图。论文的实验也验证了这一点：vanilla Qwen3-Embedding-8B 直接加入 summary 后，平均检索表现从 **44.70 降至 35.56**。

因此 MiA-Emb 需要同时解决：

- 保留 query 的局部检索意图；
- 注入 Mindscape 的全局语义；
- 学会什么时候利用哪些全局信息。

论文为此设计了 **Residual Integration + Mindscape-Aware Training**。

### 挑战 3：长上下文数据集缺少 query–evidence 监督

NarrativeQA 等数据集通常只有 question-answer pair，并没有标出“答案具体依赖哪些 chunks / graph nodes”。但训练 retriever 恰恰需要这种监督。因此论文自动构造 **silver evidence**：

`查询增强→ 集成检索→ 投票→ LLM过滤`

最终构建出 **27,117 个问题**的检索监督数据，平均每个问题包含 **2.3 个 silver chunks** 和 **2.9 个 silver nodes**。

Oracle 实验进一步验证了这些 silver chunks 的质量：只使用平均 2.3 个 silver chunks，F1 达到 **52.91**，甚至高于使用完整书籍上下文的 **50.79**。

### 挑战 4：只增强 Retriever 会造成 Retriever–Generator 不对称

如果 retriever 在 Mindscape 的指导下找到了更合适的证据，但 generator 没有看到同一个 Mindscape，那么 generator 仍可能无法理解：

- 为什么这些 chunks 与 query 相关；
- 不同 chunks 之间有什么联系；
- 局部证据应该如何放回整个文档语境中解释。

因此论我们进一步训练 **MiA-Gen**，让 retrieval 和 generation 共享同一全局语义条件。


## 核心创新点与贡献

> **我主要参与方法、论文逻辑梳理与核心贡献提炼、表达优化和方法框架图绘制；参与 Rebuttal，并针对性提出改进思路，提升论文整体逻辑性与完整性。** 下面介绍论文整体的贡献点、方法和实验。

### 1. 提出 Mindscape-Aware RAG 的统一框架

论文首次将 **mindscape-aware retrieval 和 generation** 统一为一个 conditioning paradigm：

\[
q, S \rightarrow C_{ret}, S \rightarrow a
\]

相比 vanilla RAG 的：

\[
q \rightarrow C_{ret} \rightarrow a
\]

关键变化是让 **Mindscape \(S\)** 同时进入 retrieval 和 generation。

### 2. 提出 MiA-Emb：利用全局语义增强 Query Representation

不同于主要增强 chunk representation 的 context-aware retrieval，MiA-Emb 将全局语义注入 **query 表示**，让 query 主动靠近当前文档正确的语义区域。同时使用 residual integration 保留原始 query semantics，并通过 chunk/node 多任务对比学习训练。

### 3. 提出 MiA-Gen：在同一 Mindscape 下进行证据整合

MiA-Gen 将：`Mindscape + Retrieved Chunks + Query` 共同作为输入，并使用包含 QA 与 claim verification 的多范式数据进行训练，使生成器学习在全局语义框架下解释和整合局部证据。

### 4. 自动构造 Chunk-Level 与 Node-Level Silver Supervision

针对长上下文 benchmark 缺乏 evidence annotation 的问题，论文设计自动化 silver evidence construction，为 MiA-Emb 同时构建 chunk retrieval 与 node retrieval 监督。


## 方法

### 1 总体框架

![MiA-RAG 的层次摘要、MiA-Emb 与 MiA-Gen 流程](/assets/research/mia-rag/overview.png)

MiA-RAG 包含三个核心部分：

1. **分层 Mindscape 构建**
2. **MiA-Emb：Mindscape-Aware 检索器**
3. **MiA-Gen：Mindscape-Aware 生成器**

## 2 分层 Mindscape 构建

论文通过 bottom-up hierarchical summarization 构造 Mindscape。

首先，对每个 chunk (c_i) 生成局部摘要，随后按照原文顺序拼接所有 chunk summaries，再进行一次全局总结，得到 document-level Mindscape。

> 为什么采用层次化摘要？直接对超长文档做一次总结会受到上下文长度限制。先局部、再全局，可以逐层压缩文档，并保留整体结构。此外，Mindscape 是文档级、query-independent 的，因此同一文档只需预计算一次，后续所有 query 均可复用。


## 3 Mindscape-Aware 检索器训练

### 用银标数据补足证据监督

从 NarrativeQA 的query-answer 对出发，分别使用问题、问题＋答案、答案进行候选检索，经投票与 LLM 过滤获得支持片段；图节点证据用类似方法构建。最终得到 **27,117 个问题**的监督数据，平均每题有 2.3 个银标片段和 2.9 个节点。silver 标是自动构建的参考证据，不等于完全由人工确认的 golden standard。

### 保留问题含义，同时注入文档 mindscape

以 Qwen3-Embedding-8B 为基础，将指令、问题、查询分隔符、摘要和检索任务分隔符一起编码。任务 token 区分片段与节点检索。

查询表示采用残差融合：**q̃ = δ·h_query + (1−δ)·h_task**。查询分隔位置保留局部意图，读完摘要后的任务位置提供全局信息。

训练使用片段检索和节点检索的联合 InfoNCE 对比损失，权重 β=0.5。LoRA rank=128、alpha=256，学习率 1e-4，batch size=4，训练 2,000 steps，温度参数 0.01。

## 4 Mindscape-Aware 生成器训练

更好的检索器会找到依赖全局语境才能理解的片段。如果生成器没有接触同样的语境，检索收益可能无法转化为答案质量。因此，MiA-Gen 以“指令＋摘要＋检索片段＋问题”作为输入，学习整合证据并生成答案。

使用 **NarrativeQA 问答与 CLIPPER 声明验证**构建联合训练语料：前者把银标证据与无关片段混合，后者使用 MiA-Emb 的实际检索结果，模拟推理阶段的噪声。每个问题使用 3／5／10 个片段构建多种输入，避免训练只适应单一检索长度。

MiA-Gen 对 Qwen2.5-14B-Instruct 进行**全参数微调**，采用自回归交叉熵，学习率 1e-5，batch size=2，训练 2,000 steps。

## 实验

原文第 4 节、附录 C 使用五组主评估结果：NarrativeQA、∞Bench-EN.MC、DetectiveQA 中文、DetectiveQA 英文、NoCha。

- NarrativeQA：556 个评估问题，平均文档约 83k tokens，评价 F1、EM 和检索 Recall。
- ∞Bench-EN.MC：229 个问题，平均约 184k tokens，评价选择题准确率。
- DetectiveQA：中英文合计 1,200 个问题，平均约 118k tokens，评价准确率和 Recall。
- NoCha：126 个评估查询，平均约 139k tokens，使用成对判断准确率 Pairwise Accuracy。

NarrativeQA 在未见书籍上做域内测试，其他任务用于跨域／跨语言评价。对比 Vanilla-RAG、HippoRAG-v2、MemoRAG、RAPTOR、SitEmb，以及只增强检索器或只增强生成器的变体；主实验统一比较 top-3／5／10 的检索预算。

主框架为 **8B 检索器＋14B 生成器**。“14B 系统优于 72B 基线”指这些实验设置中的生成器规模比较；72B 对照使用 4-bit 量化，不能理解为对所有 72B 模型能力的普遍结论。

## 检索提升是否转化为任务收益

### 检索结果

原文表 3 中，NarrativeQA 的 Recall@3／5／10 为 **62.68／75.92／88.09%**，Qwen 基线为 41.81／54.51／71.13%；去掉摘要的同类训练模型为 55.62／67.19／83.65%。

DetectiveQA 中文 Recall@10 为 **72.50%**，英文为 **69.75%**；Qwen 基线对应 55.58%、49.25%。这些比较同时支持监督训练的作用与全局摘要在训练基础上的额外收益。

### 成本分析

8×H20 上 MiA-Emb 训练约 21 小时，MiA-Gen 约 28 小时。在 2×A100 40GB 上使用 Qwen2.5-7B 生成摘要，平均每本约 118k tokens 的书预处理约 **24.79 秒**，可在该文档的后续查询中复用。

## 机制分析：摘要怎样影响模型内部表示

**选择性检索：** 嵌入几何分析显示，查询更接近所属文档的语义子空间。图 5 所示书籍的平均投影角从 43.5° 降到 37.1°，支持全局语境引导检索方向的解释。

**查询理解增强：** 对两个模型均能完整召回证据的 100 个问题，分析各层残差流中的检索能力及注意力。MiA-Emb 中层召回提升与对摘要的注意力上升同时出现，案例中注意力聚焦于相关人物、事件和地点。这是机制线索，样本选择和相关性分析限制了外推范围。

**证据整合：** 提出 MCEA 指标，观察摘要与问题对相关片段的注意力关联。把正确摘要换成等长无关文本后，MiA-Gen 的 MCEA 明显下降，支持其证据整合依赖有效全局信息。原文明确将 MCEA 视为注意力诊断工具，不能直接用原始数值给不同模型做通用能力排名。
